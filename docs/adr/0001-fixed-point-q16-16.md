# ADR-0001：数値表現は`int`のQ16.16固定小数点にする

## 状態

採用

## 背景

格闘コアは固定60fpsで更新し、後からロールバックとリプレイを載せます。どちらも、同じ入力列から機種を問わず同じ状態が得られること（以後「再現性」）が前提です。

一次情報として次を確認しました。

- .NETの`Math.Sin`、`Math.Cos`、`Math.Atan2`の公式リファレンスは、Cランタイムを呼ぶため結果がOSやアーキテクチャで異なり得ると明記しています。
- C#言語仕様8.3.7は、浮動小数点演算を結果型より高い精度で実行することを許しています。
- Godot.NET.Sdk 4.7.2の`Sdk.targets`では、`real_t`は既定でfloat32です。
- Godotの公式ドキュメントは、物理エンジンの挙動に再現性が無いと警告しています。

| 軸 | 固定小数点`long` Q32.32 | 固定小数点`int` Q16.16 | `float` |
|---|---|---|---|
| 機種間の同一結果 | 整数演算なので保証される | 同左 | 三角関数は仕様上保証されない |
| 乗算の中間値 | `Int128`か分割乗算が要る | `long`に広げて乗算し、戻すだけ | 不要 |
| 小数部の精度 | 2^-32 | 2^-16（約0.000015） | 仮数24bit |
| 整数部の範囲 | ±2^31 | ±32,768 | 広い |
| Godotへの受け渡し | `long`から`float`への一方向変換 | `int`から`float`への一方向変換 | そのまま |

## 決定

Coreの座標、速度、距離などの連続量は、すべて`Fix16`（`int`のQ16.16固定小数点）で表します。

- 型は`readonly record struct Fix16(int Raw)`です。`Raw`は実数値の65536倍で、定数`One`は65536です。
- 加減算は`checked`で行い、あふれは`OverflowException`にします。Coreの`csproj`で`CheckForOverflowUnderflow`をtrueにします。
- 乗算は`(int)(((long)a.Raw * b.Raw) >> 16)`です。負数の右シフトは算術シフトなので、結果は負の無限大方向へ丸まります。
- 除算は`(int)(((long)a.Raw << 16) / b.Raw)`です。C#の整数除算なので、結果はゼロ方向へ丸まります。0除算は`DivideByZeroException`のままにします。
- 乗算と除算の結果を`int`へ戻すキャストも`checked`で、収まらなければ`OverflowException`です。
- 実数からの変換はJSON読み込み時だけ行います（ADR-0004）。
- Game側への変換は`Raw / 65536f`をGame側の1か所（`FixConvert`）で行い、Coreは`float`を返しません。
- 座標成分の絶対値は1024m以下に保ちます（ADR-0002）。2点の差の各成分は2048m以下で、`Raw`は2^27以下です。3成分の二乗和（`long`のQ32.32）は2^56未満なので、`long`の上限（2^63未満）を超えません。

## 影響

- `Fix16`の演算と、丸め方向・あふれ・0除算のテストを最初に実装します。
- Coreでは`float`と`double`を使いません。ADR-0009の禁止シンボルと、公開APIに`float`と`double`が現れないことを確かめるテストで守ります。
- 制約条件C-01として「`Fix16`の全演算は整数演算だけで閉じ、同じ入力に同じ結果を返す」を置き、`Fix16Tests`で確かめます。
