# ADR-0025：キャラの見た目は判定データから組み立てた図形にする

## 状態

採用

## 背景

ADR-0006は「お客様は攻撃が当たったかどうかを画面の見た目で判断する」ことを前提に、判定を手足に沿ったカプセルにしました。最初の到達点（ADR-0023）ではキャラを箱1個で描いたため、手足が見えず、どの技がどこに当たったのかを画面から読めませんでした。見た目の作り込みは後回しにできても、手足の有無は格闘ゲームとして成り立つかどうかを分けます。

| 軸 | 箱1個 | 判定データから組み立てた図形 | モデルとアニメーション |
|---|---|---|---|
| 手足と技の見え方 | 手足が無く、技の違いが見えない | 攻撃する手足が判定の位置へ伸び、技の違いが見える | 動きが滑らかで、技の違いがよく見える |
| 見た目と判定の一致 | 判定が箱の外にあり、ずれて見える | 手足の先端が攻撃カプセルの端点そのもので、ずれない | `BakeCapsules`（ADR-0006）で合わせるが、補間で微妙にずれる |
| 必要な資産 | 無し | 無し | モデル、リグ、アニメーションクリップ |
| 作る手間 | 最小 | 部品10個と姿勢の表 | 大きい |

## 決定

- キャラは頭、胴、左右の上腕、前腕、大腿、下腿の10個の図形（球とカプセル）で描きます。寸法はGame側の定数で、キャラ座標（前が+X、右が+Z、上が+Y）で置きます。
- 姿勢は`PlayerState.State`と`StateFrame`から毎フレーム決めます。立ち、歩き、しゃがみ、ガード、やられ、ダウン、起き上がり、投げ、攻撃の姿勢を持ちます。
- 攻撃の手足は技のコマンドで決めます。Pを含む技は右腕、Kを含む技は右脚です。判定区間中は、その手足の先端を区間の最初の攻撃カプセルの`B`に置きます。発生中と硬直中は構えの位置との間を補間します。投げは判定区間を持たないので、両腕を前へ伸ばした固定の姿勢にし、技の間は両腕を明るい色にします。
- 手足の先端を目標へ届かせる計算は、根元から目標までの距離を2本の長さの和で抑え、余弦定理で関節を求める2関節の解析的IKです。
- 当たった側は`LastHitKind`が`None`以外になったフレームから6フレーム白くし、判定区間中の攻撃する手足は明るい色にします。
- 本物のモデルとアニメーションへ差し替える時は、ADR-0006の`BakeCapsules`でカプセルを書き出し、Coreと技データは変えません。

## 影響

- 攻撃が当たって見えるのに当たらない、触れていないのに当たる、という見た目と判定のずれが起きません。
- 描画は`src/Game/View/CharacterFigure.cs`が担い、`FightScreenBase`は状態を渡すだけになります。
- 手足の動きは区間ごとの姿勢の補間なので、滑らかさはモデルとアニメーションに劣ります。
